# Cybernet AI — Конструктор скриптов

Контекст проекта для Claude Code. Собран после длительной отладки, чтобы не
повторять уже пройденные ошибки.

## Что это

Одностраничное приложение (vanilla JS, без сборки) для построения диалоговых
блок-схем колл-центра. Развёрнуто на Vercel из GitHub.

**Файлы:**
- `script.js` — вся логика (~11 000 строк). Основной файл.
- `index.html` — разметка, фавиконка вшита как data-URI.
- `styles.css` — стили, светлая и тёмная темы через CSS-переменные.
- `supabase-client.js` — облачная синхронизация (профили, эталоны, настройки).
- `api/ai.js` — серверный прокси к LLM на Vercel. Ключи провайдеров живут
  только здесь, в переменных окружения.
- `db/schema.sql` — схема таблиц, индексы и RLS-политики. Выполнять в
  Supabase → SQL Editor, скрипт идемпотентный.
- `tests/` — регрессионные тесты, запуск `npm test`.

**Важно:** файлы в CRLF. Сохранять переводы строк при записи, иначе диффы
раздуваются на весь файл. Это проверяется тестом.

## Как проверять изменения

```bash
npm test        # весь набор: безопасность, генерация, раскладка, целостность
npm run check   # только синтаксис трёх отгружаемых файлов
```

Тесты вытаскивают функции прямо из `script.js` по имени и исполняют — сборки и
модулей нет, поэтому проверяется ровно тот код, который поедет в продакшен, без
параллельной копии, которая разъедется с оригиналом. Обвязка в
`tests/helpers.js`; `loadFunction(name, file, deps)` умеет принести с собой
свободные переменные.

## Проверка развёрнутой версии

В начале `script.js` стоит `CYBERNET_BUILD`, он логируется в консоль при
загрузке вместе с именем реально загруженного файла. Если правки «не работают» —
сначала сверить эту строку с ожидаемой версией. Много времени было потеряно на
отладку кода, который просто не доехал до браузера.

Токены `?v=` у `styles.css`, `script.js` и `supabase-client.js` бампятся
**вместе** с `CYBERNET_BUILD`. Раньше они жили порознь и протухали по одному
(стили оставались на октябрьском токене), из-за чего часть правок молча не
доезжала. Это проверяется тестом; страхует ещё и `Cache-Control:
must-revalidate` в `vercel.json`.

Текущая версия: `2026-08-04-v64-security-hardening`.

## Безопасность — что нельзя ломать

Разобрано по итогам внешнего аудита; каждый пункт закрыт тестом в
`tests/security.test.js`.

- **`/api/ai` пускает только вошедших.** Проверяется JWT Supabase через
  `/auth/v1/user` обычным `fetch` — без SDK и **без service-role ключа**, его
  здесь быть не должно. До этого эндпоинт был полностью открыт: проверка
  `if (origin && origin !== ALLOW)` пропускала запросы **без** заголовка Origin
  (то есть любой curl), а лимитер делал `hits.clear()`, обнуляя счётчик сразу
  всем. Лимит теперь по `user.id`, протухшие записи вычищаются поштучно.
- **Ключи провайдеров не уезжают в БД.** `stripProviderKeys` в
  `cloudSaveSettings` — единственная точка записи, срезает `apiKey`,
  `geminiApiKey`, `openaiApiKey`. Ключи остаются только в localStorage.
- **id блоков обеззараживаются на ВСЕХ входах** через `safeProfile()`.
  `esc()` в inline-обработчиках **не защищает**: HTML-парсер раскодирует
  `&#39;` обратно в апостроф до того, как строку разберёт JS. Единственная
  защита — набор допустимых символов в id. Пути: JSON-импорт, CSV-импорт,
  импорт эталона из файла, облачные эталоны, `useReferenceAsProfile`,
  `getRefProfile` (страховка на чтении), вывод модели.
- **Наружу не отдаются тела ошибок провайдера** — только общая фраза и `ref`
  для поиска в логах Vercel.

Осознанно НЕ сделано: CSP (сначала надо заменить ~33 инлайновых обработчика на
делегирование, иначе строгий CSP ломает приложение) и сборка/минификация.

## Генерация скриптов — устройство

Два независимых пути, и это главный источник путаницы:

**1. STRUCTURE MODE** — включается при `activeRefs.length === 1 && genMode === 'exact'`.
Копирует структуру эталона 1:1 (блоки, позиции, связи, геометрия стрелок) и
просит модель написать только тексты. Собирает **собственный промпт** и НЕ
использует `aiPrompts.generate_system` — правки пользователя в редакторе
промптов сюда не попадают (об этом выводится предупреждение).

**2. Общий путь** — всё остальное. Использует `aiPrompts.generate_system` +
`generate_user` с подстановками.

Режимы (`gs-mode`): `exact` (структура эталона), `style` (только тон реплик),
`blend` (смешать несколько эталонов, показывается от 2 эталонов).

### Что уже вынесено в код, а не в промпт

Модель систематически игнорировала часть правил, поэтому они реализованы
детерминированно. Не переносить обратно в промпт:

- единственное приветствие (остальные вырезаются регулярками RU/UZ);
- срезание вопроса у блоков без веток-ответов (но НЕ если блок ведёт в роутер,
  который ветвится);
- блоки-маршрутизаторы («Ответ клиента», «Любой ответ») и системные директивы
  («Установка русского языка», «Проверка языка в базе») не отправляются модели
  и сохраняются дословно;
- двуязычный зонд «Алло, Assalomu aleykum /Здравствуйте» — фиксированный,
  клиент по нему выбирает язык;
- стартовый маркер («Начало разговора») — без речи;
- закреплённые структурные заголовки: Рус, Уз, Да, Нет, 1ый раз, Молчание;
- исправление «Меня зовут <должность>» → «Я <должность>»;
- удаление дубликатов блоков с перенаправлением веток;
- порядок генерации — обходом графа от старта, чтобы каждый блок видел уже
  написанные реплики предшественников.

### Диагностика в консоли

После генерации печатается: покрытие блоков, число убранных приветствий и
лишних вопросов, качество реплик (доля с цифрами, пустышки, средняя длина,
разных фактов из базы), состав по типам блоков.

## Известные ограничения и грабли

- **Кириллица в регулярках JS:** `\w` не покрывает русские буквы. Дважды ловил
  на этом баги — использовать явные классы `[а-яё]`.
- **Лимит ответа модели** масштабируется от запрошенного размера
  (~260 токенов на блок). Плоский лимит обрезал большие скрипты.
- **Gemini 2.5+/3.x «думают»**, и токены размышлений списываются с
  `maxOutputTokens` — при большом промпте ответ приходит пустым. Отключено
  через `thinkingConfig`.
- **Gemini 3.5 Flash** часто отдаёт 503 (перегрузка). Рабочий выбор —
  **Gemini 3.1 Flash Lite**: по замерам качество выше, чем у GPT-4o mini
  (цифры в 52% реплик против 20%, 36 разных фактов против 14).
- **Автоповтор** при 429/500/502/503 и обрывах сети: до 3 попыток с паузами
  2с → 4с → 8с. Без него одна упавшая порция теряла всю генерацию.
- **localStorage ~5 МБ.** Бэкапы версий хранят только активный профиль; при
  переполнении старые снимки удаляются автоматически.
- **Удаление профилей** требует «надгробий»: при загрузке облако полностью
  заменяет локальные профили, поэтому удалённые помечаются, чтобы не
  воскресали.

## Стрелки на канве

Роутер строит строго ортогональные маршруты. Точки изгиба редактируются:
клик по стрелке → синие точки, тянуть линию → новый изгиб, двойной клик →
удалить, кнопки «Убрать лишние точки» и «Выпрямить».

**Что НЕ делать:** перетаскивание концов стрелки к произвольной точке блока
уже пробовали — свободные точки конфликтуют с ортогональным роутером, линия
проходит мимо ручек, схема разваливается. Откачено. Если возвращаться — только
через фиксированные точки привязки на блоке, как в Visio.

Ручки рисуются в отдельном слое `.canvas-edges-top` поверх блоков, иначе
попавшие под блок недоступны для клика.

## База знаний

Поле в окне генерации, хранится в localStorage (`cybernet_knowledge_v1`),
подставляется в оба пути генерации. Ссылки приложение НЕ загружает — только
запросы к API модели. Факты нужно вставлять текстом.

База считается главным источником: и факты, и описанная в ней логика сценария
имеют приоритет над типовым планом из промпта.
